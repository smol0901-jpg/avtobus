# Рейзино Транзит — PWA-расписание автобусов

Офлайн-приложение: Большое Рейзино ↔ Красноармейский пр-т / ул. Нестерова (Гатчина).
Работает без интернета и установки: достаточно открыть ссылку на GitHub Pages.

## Возможности
- Крупный блок «Ближайший рейс» с обратным отсчётом до минут и секунд.
- Фильтр по линиям, закрепление любимых линий звёздочкой, показ ушедших рейсов.
- Учёт выходных, праздничных дней РФ (список редактируется в профиле) и рейсов «только будни».
- Оповещения за 5 минут до ближайшего рейса (Web Notifications, когда приложение открыто).
- Свои маршруты в текстовом формате + экспорт/импорт JSON для переноса между устройствами.
- Шаблоны JSON (data/): электрички, автобусы и пустой каркас — загрузка/скачивание во вкладке «Маршруты».
- Баннер актуальности данных: сезон (летний/зимний), дата обновления, счётчик дней до смены графика.
- Кнопка «Сообщить об изменении расписания» — открывает диалог ВКонтакте с готовым текстом запроса.
- Светлая/тёмная/системная тема, установка как PWA на телефон, полностью офлайн после первого визита.

## Запуск на GitHub Pages
1. Создайте публичный репозиторий и загрузите содержимое этой папки в корень (включая `.nojekyll`).
2. Settings → Pages → Source: `Deploy from a branch`, Branch: `main`, folder: `/(root)`. Сохраните.
3. Через минуту откройте `https://<логин>.github.io/<репозиторий>/` — приложение работает.
4. На телефоне: меню браузера → «Добавить на главный экран» (или кнопка «Установить» в профиле).

Всё настроено на относительные пути (`./`, `sw.js`), поэтому проект корректно работает
и в подпапке вида `login.github.io/repo/`, и с любого домена.

## Обновление версии приложения
После изменения кода или расписания:
1. Обновите `VERSION` в `js/data.js` (например, `2.1.1`).
2. Обновите `V` в `sw.js` на то же значение с префиксом: `rt-2.1.1`.
3. Сделайте push. Пользователи увидят кнопку «Обновить приложение» в профиле
   (навигация также берётся из сети, поэтому свежая версия подхватывается быстро).

## Данные
Расписание лежит в `js/data.js` (компактный формат: время + код линии + минуты в пути + `w` для будней).
Свои маршруты добавляются во вкладке «Маршруты», резервная копия — «Экспорт/Импорт JSON» в профиле.
Шаблоны для загрузки новых данных — в папке `data/` (формат описан в `data/README.md`).

**Почему нет автоскрапинга:** rasp.yandex.ru и rzd.ru не отдают данные чужому сайту (CORS запрещает
межсайтовые запросы, а Яндекс требует API-ключ). Для парсинга нужен сервер-прослойка (например,
GitHub Actions раз в неделю скачивает страницу и коммитит обновлённый JSON — тогда приложение сможет
подтягивать его кнопкой «Обновить»). Сейчас расписание обновляет автор: правит `js/data.js` или
присылает пользователям новый JSON-шаблон; пользователи получают обновление кнопкой
«Обновить приложение» либо загружают шаблон из вкладки «Маршруты».

## Структура
```
index.html            каркас страницы, SVG-иконки вкладок
manifest.webmanifest  PWA-манифест (иконки, shortcuts #/sched, #/routes)
sw.js                 офлайн-кэш: navigation — сеть-первой, статика — кэш-первой
offline.html          заглушка при первом офлайн-визите
css/base.css          темы, каркас, шапка, вкладки
css/components.css    карточки, hero, строки расписания, формы, диалоги
js/app.js             точка входа: рендер, обработчики, уведомления, SW
js/views.js           экраны: Рейсы / Маршруты / Профиль / О проекте
js/store.js           localStorage, миграция rt.v2→rt.v3, разбор расписания, импорт/экспорт
js/data.js            VERSION, встроенное расписание, праздники по умолчанию
js/time.js            время, плюрализация, метки дат
js/ui.js              экранирование, тосты, модальные диалоги, вибрация
js/vk.js              ссылки и готовые тексты сообщений автору в ВКонтакте
data/                 шаблоны JSON для импорта (автобусы, электрички, каркас) + описание формата
icons/                SVG + PNG 192/512
.nojekyll             отключает обработку Jekyll на GitHub Pages
```
